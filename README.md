## 当前规则基线

- 开战前在「灵契编成」中从 8 名角色选择 4 名。
- 每名角色拥有 15–18 种专属候选牌（含 1 张觉醒牌与 2 张 SSR），玩家为每名角色选择 8 张，同名最多 2 张（觉醒牌限 1 张，SSR 可带 2 张），总牌库 32 张。
- 8 名角色均有纯数据定义的基础被动，由规则事件队列统一触发。
- 双方核心 30 生命；空牌库时再次抽牌直接判负。
- 每回合鬼火回复至 2，基础出击消耗 1 点，出牌按牌面消耗 1 或 2 点（瞬发等另按关键词处理）。
- 每回合可免费将一名角色提升 1 勾玉，上限 3 勾。
- 一名角色占据中央前线，其余角色位于准备区。桌面端可拖动后场角色到前线出击，触屏可点选角色后使用出击按钮。
- 已接入战斗牌、法术牌、形态牌与幻境牌；幻境拥有独立耐久，可被基础出击或战斗牌指定攻击并摧毁。
- 138 种卡牌的效果均已规范化为可组合的“条件 + 动作 + 目标”步骤，由规则层按顺序解释执行。
- 卡牌效果通过纯数据结算栈执行；带响应条件的卡牌会在原效果前打开响应窗口。
- 已接入响应、瞬发、贯通、眩晕、远程、运势、鼓舞、充能、倒计时、占卜、化身、融合、协战、投射，以及连击、先攻、暴击、不屈、爆能 等 26 个可复用关键词。费用、时机、伤害路由、交战、自动出牌、玩家选择和状态资源均由关键词注册表驱动。
- **觉醒与 SSR**：每名角色 1 张觉醒牌（2 勾 1 费，+1/+1 并把被动永久升级为觉醒版，气绝不丢失）与 2 张传说 SSR（3 勾 1–2 费，牌组同名限 2，仅收集获取）；攻击成长走独立通道，不被后续形态覆盖。
- **爆能**（新关键词）：出击时消耗来源角色全部充能，每点按卡牌折算为本次攻击加成（读即消耗）。
- 扩展包「不夜宴席」新增 7 个关键词：**蓄力**（附着式神，回合开始推进计数，成熟后自动结算）、**连引**（抽取牌库中下一张同式神牌）、**赐能**（消耗充能解锁强化步骤）、**烹饪**（旧HTML/JS仍为历史近似；Godot已使用真实食材实例与合成机制）、**入夜**（预约指定回合的延迟效果）、**起源**（将同名牌洗回牌库）、**专注**（本回合首张牌时追加抽牌）。
- **秘闻阁**收藏与御札经济：初始拥有全部默认构筑卡（常见/稀有/史诗各 2 张，觉醒牌限 1 张），秘闻卷每包 5 张（常见 58.5% / 稀有 33% / 史诗 6% / 传说 2.5%，25 包保底史诗、40 包独立保底传说），重复卡自动折算御札；对局胜利 +300 / 失败 +150 御札；御札可按稀有度定价合成缺失卡（传说 2400）。编成页可开启「全卡试用」，不增加实际收藏即可使用全部卡牌；关闭后卡组构筑受收藏数量与牌组同名上限双重门控，收藏持久化在浏览器本地。
- 战报通过顶部按钮打开独立滚动面板，记录数量不会改变战场尺寸。
- 本地 AI 通过纯评分模块选择合法命令，对局状态支持带版本的 JSON 序列化与恢复。
- 顶部「存档」提供单本地存档槽；存档同时保存初始快照、当前状态和玩家/AI 双方命令日志，并在保存与读取时通过确定性重放校验一致性。
- 「存档」同时提供当前对局与本地存档的只读回放入口；可逐命令前进、后退、跳转或自动播放，回放使用检查点和有限的按需帧缓存，与实时对局完全隔离。
- 当前对局和本地存档都可导出为版本化 JSON；导入文件会经过相同的确定性校验并直接进入只读回放，不覆盖实时对局或浏览器存档。

## 战斗表现层（v6「枢夜交战」）

- **战斗界面**：明确五行「敌方准备 / 敌方前线 / 指令 / 己方前线 / 己方准备」，独立左侧核心资源栏、右侧牌库和结束回合、底部完整手牌。前线与准备区同尺寸；手机四角色同排、核心资源上下分区、牌库控制移到己方资源下方。长手牌整卡横向滚动，不按张数缩成切片。桌面左栏承担卡牌预览与角色详情。
- **编成界面**：宣纸画册风。角色名录大卡 + 悬停详情条（被动全文与卡池概况）；卡组构筑带角色页签、被动档案、稀有度配色与一键填充。
- **交互**：点选出击 + 拖拽己方角色到敌方前线/幻境直接出击；悬停任意单位展开检视浮层（被动与全部状态）。
- **动效**：抽牌入场、出击前冲、受击抖动、气绝崩落、升勾金环、伤害飘字、回合横幅、结案印章等关键帧，并支持 `prefers-reduced-motion`。
- **音频**：BGM 由三层乐器（持续音 + 和筝拨弦 + 尺八旋律 + 太鼓）按四小节和声循环实时合成，编成用阳调式、战斗用平调子；音效新增抽牌、护盾、幻境部署、占卜、选择、错误与 UI 叩击等，并带音乐闪避。


### three.js 引入与降级

`index.html` 使用原生 importmap，锁定 **three@0.180.0**：`three` 映射到 `https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.js`，`three/addons/` 映射到同版本 `examples/jsm/`。没有构建链、npm 运行依赖或后处理。`battle-fx.js` 动态 `import('three')`，CDN 失败、WebGL2 不可用、context 丢失时自动退回 DOM/CSS，不影响对局。

3D 是 `.game-main` 上透明且 `pointer-events: none` 的画布。手牌与左侧预览使用透视、指针点光源和按稀有度设置的物理全息边框，原有 card-holo 材质保留。静态低对比灯火深度场提供氛围；只在交战、气绝、核心受击、幻境部署与破碎时播放有限时长的光环/碎片。游戏状态、目标合法性与命令结算继续走 `game-core`；升级可用性也直接查询 facade，包括气绝角色。

遵循 [Rendering on Demand](https://threejs.org/manual/en/rendering-on-demand.html)：状态、尺寸、指针变化请求帧，特效结束停 RAF，静止悬停不维持循环。遵循 [Cleanup](https://threejs.org/manual/en/cleanup.html)：每段特效结束释放 geometry/material，离场或终局释放全部场景资源与 renderer 内部缓存。整个页面保留唯一 canvas/WebGL context；再次进入以**同一 context**重建已被 dispose 的 renderer wrapper，避免调用终结后的 wrapper 或增加 context。`getBattleFxDiagnostics()` 是只读表现诊断，不暴露游戏修改入口。

菜单内「3D 表现」开关以本地偏好持久化。`prefers-reduced-motion` 动态变化时立即销毁 3D 资源并保留 CSS 静态反馈；关闭偏好后按需恢复。移动端 1×，桌面不超过 1.5×，无后处理。战斗布局不依赖 WebGL，手机采用纵向完整战场和可横滑手牌，短视口可正常纵向滚动。

`npm run audit` 原本引用项目外缺失的 ark-ui-skill 脚本，现改为项目内 `scripts/audit-ui.mjs`。此检查覆盖语义、ARIA 引用、重复 ID、资源与 import 存在性、断点、关键布局约束和 three.js 引入边界，**不声称与原外部审计等价**；几何重叠与真实操作由 `output/playwright/v6-play-match.js` 验证。

## 添加角色

1. 在 `game-content.js` 添加角色定义。
2. 为该角色添加至少 12 种卡牌，并用 `starterCopies` 配置 8 张默认构筑。
3. 用 `effects` 组合卡牌步骤；需要新动作或条件时，再在 `game-core.js` 注册对应处理器。
4. 把角色卡面放入 `assets/`，不引入未授权的商业游戏素材。
5. 运行内容契约与规则测试。

卡牌效果步骤使用以下结构：

```js
effects: [
  { condition: 'always', action: 'damage', target: 'selected-enemy', value: 1 },
  { condition: 'target-alive', action: 'apply-brittle', target: 'selected-enemy', value: 1 },
]
```

`condition` 决定该步骤是否执行，`action` 只负责状态变更，`target` 明确作用对象。旧的 `effect` 与 `value` 字段暂时保留为兼容入口，不应再承载新的组合逻辑。

响应牌额外声明出牌时机和可响应动作：

```js
{
  timing: 'response',
  responseTo: ['damage', 'assault', 'shield'],
}
```

当待结算效果与 `responseTo` 匹配时，规则层暂停原效果并把优先权交给效果控制者的对手。打出响应牌会将其压入 LIFO 结算栈并把优先权交给另一方；第一次放弃只转移优先权，双方连续放弃才结算当前栈顶。响应牌最多嵌套 8 层，双方均无合法响应时自动跳过空窗口。

已实现关键词遵循以下规则：

- **响应**：待结算动作匹配 `responseTo` 时打开响应窗口；支持双方交替优先权、连续两次放弃、LIFO 连锁结算和 8 层嵌套上限。
- **瞬发**：仅在持有者自己的行动回合生效；每回合打出的第一张瞬发牌费用为 0，使用后本回合其余瞬发牌恢复原费用。
- **贯通**：攻击先结算护盾和角色生命，超过目标剩余生命的真实溢出伤害转移给敌方核心；击倒式神本身不额外造成核心伤害。
- **眩晕**：角色无法出击或反击，在其持有者回合结束时减少持续回合。内部存档字段继续使用 `frozen` 以保持兼容。
- **远程**：带远程的战斗牌从角色当前位置发动攻击；攻击者不进入前线、己方原前线不变，且本次不受反击。
- **运势**：结算前通过确定性 RNG 投掷 D6；达到卡牌阈值时才执行 `fortune-success` 效果步骤。
- **鼓舞**：鼓舞状态累加在玩家身上；下一次基础出击、普通战斗牌或远程战斗牌会获得全部攻击与护盾加成，并只消费实际激活的鼓舞状态。
- **充能**：角色在己方回合开始时按配置增长资源；卡牌用 `chargeCost` 声明消耗，资源只在原卡真正开始结算前支付一次。
- **倒计时**：具有倒计时的幻境在持有者回合开始时减 1，归零后触发配置效果，再重置为卡牌声明的数值。
- **占卜**：暂停当前结算并检视牌库顶 N 张牌；玩家或 AI 必须选择一张置顶后才能恢复，选择状态可序列化。
- **化身**：己方回合抽牌后，每回合最多自动免费使用一张满足条件的化身牌，不打开响应窗口。
- **融合**：重复使用同名融合牌时为来源角色叠加声明的攻防数值，达到 `maxStacks` 后不可再用；这是适配固定四角色战场的当前语义。
- **协战**：本回合已有另一名友方角色攻击时，协战牌获得声明的攻击加成。
- **投射**：伤害自动优先命中敌方前线；前线为空时改为伤害敌方核心。

## 复用与扩展关键词

新角色复用现有关键词时，只需在 `game-content.js` 的卡牌定义中声明注册表常量，不需要修改战斗函数或 UI：

```js
keywords: [CARD_KEYWORDS.PIERCE]
```

新增关键词时，在 `game-keywords.js` 注册一个定义，并按实际机制实现所需生命周期钩子。当前框架提供：

- `onTurnStart`：重置或推进每回合关键词状态。
- `canPlayCard`：根据关键词资源和卡牌声明返回不可用原因。
- `modifyCardCost`：统一计算动态鬼火费用。
- `afterCardPlayed`：记录关键词使用状态。
- `beforeCardResolution`：在原卡效果真正结算前执行一次性资源支付。
- `effectCondition`：为数据化效果步骤提供关键词条件判定，例如 `fortune-success`。
- `damageRoute`：为自动目标伤害返回角色或核心路由，例如投射。
- `automaticCard`：声明系统自动使用卡牌的触发时机和优先级，例如化身。
- `combatOptions`：向通用交战结算提供贯通、远程等可组合参数。
- `afterCombat`：交战完成后记录跨攻击者状态，例如协战。
- `applyEffect`：接受通用 `apply-keyword` 动作，将数据化效果写入关键词自己的状态。
- `prepareCombat`：在交战开始前返回数值贡献和激活令牌；核心只汇总通用攻击、护盾参数。
- `consumeCombatActivation`：只消费准备阶段实际激活的令牌，避免条件关键词被误消耗。
- `beforeRealmTrigger` / `afterRealmTrigger`：控制幻境触发前后的计数和重置。
- `validateCard` / `validateUnit` / `validateUsage`：在启动或存档恢复时拒绝未知、重复或损坏的关键词配置。
- `costReductionLabel` / `formatStatus` / `formatUnitStatus`：向 UI 提供减费、玩家状态和角色资源文本，不在 `app.js` 判断具体关键词。

每回合使用记录和可消耗状态保存在玩家的 `keywordUsage` 中，已部署幻境会保留自己的 `uid`、`hp`、`maxHp` 和 `keywords`，待完成的占卜保存在 `pendingChoice`。恢复时会验证幻境来源、唯一身份、耐久范围、结算帧和响应优先权。对局序列化、AI 模拟和 UI 渲染读取的是同一份纯数据状态。当前存档版本为 v6。
