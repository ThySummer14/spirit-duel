# 编队操作与高清显示

2026-11-09。本批调整 Godot 编队与渲染设置，没有修改卡牌结算、构筑合法性、AI 或卡池。

## 原因与修复

原有编队代码反转了原生横向手势，还把细小滚轮位移放大为至少 72 像素的一跳。Godot 4.6.3 的网页输入实现优先处理 Y 轴，触控板横滑混入少量纵向分量时会丢掉主要的横向位移。修复前新增的方向检查复现 2 项失败。

现在原生输入遵循系统方向；网页只在编队牌池内接收完整双轴 wheel 事件，取主要轴，保留小数位移。输入以 CSS 像素归一化后转换到实际控件坐标，适配 Retina 和超采样；系统已提供的惯性不再另加延迟。右键检视打开时不会误滚动背后牌池。鼠标横拖、纵向拖牌与两侧翻页按钮继续可用。

编队将式神信息与四个入队头像放在牌池上方，扩大正式牌面展示，压低背景对比度，已放数量改为右上角小标记。底部保留八个稳定槽位，只为变化的卡牌创建控件，加入短过渡、替换取消与撤销。切换式神保留各自的浏览位置。基础能力、觉醒、资料包和策略放入式神详情弹层；搜索、筛选及全部 251 位式神仍可用。

## 分辨率与帧率

原项目已经采用 `canvas_items` 和 HiDPI，1280×800 是布局基准，并非最终渲染像素；原先 `Engine.max_fps` 也是 0。不能把本批说成从固定低分辨率、固定低帧率解锁。

网页现在按 CSS 尺寸 × `devicePixelRatio` × 画质倍率建立真实绘制缓冲区，长边上限 4096。提供 75%、100%、125%，默认 125%。导出使用 None canvas resize policy，由外层在窗口和屏幕 DPI 变化时更新画布，Godot 负责同步渲染目标。UI 逻辑尺寸保持原比例。原生客户端继续使用屏幕原生 HiDPI。

帧率设置提供跟随屏幕、60、120、144，对应实际 `Engine.max_fps`，保持 VSync 与规则时钟。设置持久化，读数直接来自渲染窗口尺寸和引擎 FPS。高分辨率不能补出原始牌图不存在的细节；较低画质可减少 GPU 负担。

## 本次验证

- Godot 4.6.3：编队专项 31 项、显示设置 8 项、相关界面流程 193 项均通过；UI 审计 393 项、0 错误。
- 编队覆盖细小位移、原生方向、拖放替换、取消、撤销、检视遮挡、浏览位置记忆、保存，以及 960×600、1280×800、1600×740 布局。
- 真实 Chrome 网页覆盖双轴事件和位移对照：DPR 2 时 DOM 横向位移 30、-15、0.5 CSS 像素，对应牌面移动 -30、16、-1 像素，误差在累计取整的 1 像素内。DPR 1 同样通过。
- Retina 1440×900 CSS 窗口，100% 为 2880×1800，125% 为 3600×2250；实际设置切换、换牌、撤销、出战及确认起手通过。前台编队及对局显示约 60 FPS，浏览器控制台 0 错误。
- 本机屏幕报告 60Hz，未在 120/144Hz 屏幕实测，不承诺所有机器都能达到所选上限。界面切换、浏览器失焦与测试截图会造成短时 FPS 波动。
- Godot 4.6.3 本地 Web 导出通过；临时构建目录 `.build/formation-polish.ie4606ps`，验收截图与日志在 `output/playwright/formation-polish-20261109/`。

指定的原版录像当前路径不存在，本批没有宣称完成该录像的逐帧还原。全库规则审计仍有 3 张已知近似、265 张未核对、1,858 张待核验；本次 UI 与渲染验证不表示全库规则已还原。
