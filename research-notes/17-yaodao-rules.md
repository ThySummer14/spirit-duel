# 妖刀姬：额外先击、响应免伤与真实击杀记录

本轮范围为普通妖刀姬 `yaodaoji` 的基础能力、觉醒、c10101–c10108 八张主体牌、一张万华皮肤，以及三个旧存档生成牌 ID。妖刀姬·呪刃是另一个独立角色，不在本轮范围。参考录像仍用于实际操作和表现；不能把未出现的妖刀交叉机制声称为录像已验证。

## 资料与版本判定

- `research-data/cards.json` 10100–10108/10109 提供原牌面数值：本体 3/4、不祥 +0/+1、见切 +1/+0、战意 +2/+2、一闪零火、万华 3/8、觉醒 +1/+1、禁锢 +0/+2。觉醒属于法术且自身没有瞬发。该快照中不祥牌文已经过期。
- [官方 2020-12-24 维护公告](https://www.taptap.cn/moment/90930908776893040) 将不祥之刃改成击杀敌方式神才抽牌。因此没有沿用快照中的命中牌手抽牌，也没有保持旧执行器的无条件抽牌。
- [官方 2022-01-26 修复公告](https://www.taptap.cn/moment/235144264613364682) 修复不祥击杀独眼小僧、自己随后被其投射气绝时遗漏抽牌。程序必须保留已经满足的击杀抽牌，不能通过检查妖刀仍存活来取消。
- [原作者狼眼的公测全卡评分](https://www.taptap.cn/moment/15223033941722667) 说明基础打脸触发瞬发、觉醒提供永久迅捷、万华先额外击中一次再进入普通交战。它是原作者经验，不伪称官方规则公告。旧二测的“首次战斗后所有牌瞬发”不适用于此版本。
- [原作者《式神浅谈第二篇：妖刀姬》](https://www.bilibili.com/opus/333469661823472230) 特别指出打脸后先用一闪会浪费瞬发，且瞬发额度与其他式神共享。因此自然零火牌获得瞬发以后依然消耗第一次瞬发；不能为玩家擅自优化掉原版的出牌顺序约束。
- [原作者战斗 FAQ](https://www.taptap.cn/moment/15225930238658237) 确认万华先击击杀无反击、打牌手有两段独立命中，护甲只获得一次。其“不祥打脸抽两张”的旧结论已被上述 2020 年公告淘汰，不能整篇照搬。
- [官方卡面属性教程](https://www.taptap.cn/moment/15218393770626608) 与[官方酒吞百科的狂气例子](https://www.taptap.cn/moment/15218530131643593) 支持护甲在下个己方回合开始清除。战斗牌力量和能力的期限与护甲不同；见切的战斗免疫与力量在该场战斗结束时失效，而未花完的护甲保留至己方下个回合开始。

## 实际规则

打脸能力依赖妖刀本人对敌方牌手造成真实伤害，护甲完全吸收、命中式神、队友打脸均不触发。基础能力只为妖刀的战斗牌赋予当回合瞬发，觉醒后命中牌手改为当回合战斗牌免费；杀念和形态不会一并免费。动态效果覆盖之后抽到或生成的完整战斗牌，牌文和费用同步显示。

觉醒作为一费法术结算印刷的 +1/+1，并给予永久迅捷。迅捷只免除出击鬼火，不增加全队普通出击次数；战斗牌仍是额外的独立攻击机会。觉醒和整局击杀记录在气绝后保留。

万华设置 3/8 形态身材并保留已有永久修正，气绝移除该形态。其额外命中发生在普通交战之前，能够先击杀对手从而避免反击；空前线对牌手有两段命中；防守时同样参与额外命中。先击杀死当前式神不会凭空把第二刀改为攻击牌手，整场战斗的完成事件只触发一次。皮肤使用完全相同的规则。

见切主动使用发起本次免疫战斗伤害的 +1 力量出击；在敌方回合被攻击时，合法自动响应支付真实费用、消耗手牌，将免疫和 +1 力量挂在原来那次防守战斗。它不建立一场额外的进攻，不改变全队出击额度，也不把免疫带到之后的战斗。

不祥只在它对应的战斗消灭敌方式神后抽牌，妖刀自己随后气绝不取消奖励。禁锢按妖刀整局实际消灭式神的记录计算额外力量，正面攻击、防守反击与额外先击都归属实际伤害来源；队友击杀不计入，刚抽到和刚生成的禁锢也取得先前击杀增强。没有把击杀改成给妖刀永久加力量。

杀念从五种真正的战斗牌中生成三张，均保留其完整费用、护甲、免疫、响应、抽牌和增强规则。它不检索或改变牌库，不制造被裁掉效果的假 token；旧 token ID 仍映射完整的原来同名牌。手牌溢出按生成顺序烧毁。

## 尚未核验的边界

双方都具有额外先击时的排序、防守眩晕与先击的全部组合，尚缺当前版本原版录像。实现暂采用攻击方先处理额外击中、眩晕防守方不反击的显式顺序，万华及皮肤保留 `verificationPending`。这一标签不能被普通程序测试抹去。

同回合先触发基础瞬发再觉醒、继而触发免费战斗牌时，之前取得的瞬发如何与无火叠加，尚缺直接实测。当前记录两个已经产生的回合效果，单位保留 `verificationPending`。单独的一闪浪费瞬发有上列原作者证据，不属于该未知边界。

同时持有多张见切的自动响应是否逐张叠加，尚缺当前原版例子；保留现有执行器每事件使用首张合法响应的模型，并在该牌标记待核验。杀念的内部抽样权重、重复规则尚无官方明确披露，目前采用五种真实战斗牌等概率有放回生成，保留待核验。程序统计覆盖池中所有牌只证明实现，不证明原版概率。

## 工程与验证记录

专属模块是 `godot/scripts/yaodao_rules.gd`，覆盖片段是 `output/godot-yaodao-20261007/overlay.json`，主代理合并后生产数据以 `godot/content/verified_rules.json` 为准。真实伤害来源、万华交战和响应续帧由共享规则层接入。

`verify_yaodao.gd` 使用完整 GameState 验证牌手伤害正反例、共享瞬发额度、一闪顺序、觉醒资源、条件抽牌、互相气绝的归属、禁锢整局增强、形态先击、防守响应、护甲寿命和完整生成池。`verify_yaodao_ui.gd` 通过原生鼠标事件验证双尺寸出牌、免费普通出击、生成牌显示、增强即时刷新和响应演出顺序；还验证万华每刀独立伤害、来源与目标、战斗卡片身份、先击与普通互伤分段，避免将两刀压成一个总数。最终测试结论以输出目录内本轮验收与日志为准。

本轮规则测试不能作为全库还原完成证明。`npm run audit:rules` 应继续报告其他角色近似项与本轮未核验边界。
