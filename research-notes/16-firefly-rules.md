# 萤草：形态瞬发、手牌增强与进入战斗区响应

本轮范围是 Godot 中原版萤草的基础能力、c10701–c10708，以及为旧存档保留的三个生成形态 ID。萤草·蒲蒲、其他角色未核对的形态/法术、JavaScript 旧执行器不在本轮已验收范围。用户指定录像仍是表现标准；录像未展示的萤草边界，不能宣称已逐帧确认。

## 已实现的规则

基础能力在使用形态时抽牌，并通过手牌描述动态赋予瞬发；全队共享一次免费瞬发额度。觉醒 +2/+2、自带瞬发，将适用范围扩展至己方形态。不会让萤草的普通法术也抽牌，不会让普通形态从卡库上永久变成瞬发。重复觉醒仍取得牌面数值；气绝时不提供存活能力，归队后恢复觉醒能力。

治愈之光在入场和己方回合开始治疗存活己方式神，不治疗牌手、不复活。勇气之光的两点力量进入全队鼓舞池，能积累，只有下一次出击消耗；不会给萤草永久加攻。安魂之光入场与回合开始实际产生鬼火，不受旧执行器虚构的四火封顶限制。三种形态设置牌面身材，替换形态时旧能力离场，气绝时清除形态。

虹彩取得 c10702/c10703/c10705 三张真实卡，保留形态入场、后续回合能力与基础能力联动；不是从牌库检索，也不制造只有加身材的假牌。手牌超过上限的生成牌依序烧毁。历史 token ID 同步覆盖完整能力，防止已有实例仍走旧效果。

萤火点点按每张手牌实例保留增强次数。在己方回合开始、萤草存活且有形态时增强；牌库、敌方回合和本次回合刚抽到的牌不会补算此前触发。指向己方式神时增加当前与最大生命，并在该目标气绝时清除普通生命增益，指向敌方式神时造成相同数值伤害。双方牌手与气绝式神非法；没有附带抽牌。动态牌文显示真实数值及增强次数。

吸取可指定角色并造成两点伤害，之后记录 +2 护甲鼓舞。鼓舞作为该牌真正生效的一部分，反制整张牌时不提前赠送护甲。

闪烁只允许指定敌方战斗区式神。自动响应条件是敌方式神从准备区进入战斗区，发生于原战斗伤害之前；已有战斗区式神再次攻击不重复触发。响应支付实际鬼火并检验萤草存活、勾玉和眩晕；不会制造额外攻击。攻击归零的临时修正到当前回合结束撤销，之后取得的永久力量不会被撤销。

## 保留核验项

闪烁与持续力量光环、进入战斗区同时发生的战斗加攻/鼓舞、后续形态替换的所有层叠顺序，尚缺当前原版完整录像。当前显式模型记录归零时的力量差额、保留后来取得的力量，并在进入响应时抑制正在发起的那次战斗加攻；c10704 保留 `verificationPending`。没有把未知边界当成已经还原，也没有用眩晕或减固定数值替代闪烁。

同一次入场事件、手牌中同时存在多张闪烁时，应响应一张还是继续响应的当前原版案例未查实。共享执行器目前每个事件使用首张合法响应牌；将这个边界同时记录到 `verificationPending`，不把当前执行器行为当作官方规范。

全库审计只有在所有近似项与未核验项处理后才应通过。本轮的程序测试验证代码按上述已记录规则工作，不能证明所有原版交叉机制都已核对。
