# 孟婆：真实移除牌库与牌名选择（2026-10-16）

本轮修复Godot中孟婆基础／觉醒与8张主体牌`c17101`–`c17108`。历史实现曾把移除牌库替换为减攻、固定伤害或强化面板，把意外之喜的弃牌直接省略；本轮不沿用这些映射。原版牌文覆盖在`godot/content/verified_rules.json`，真实移除及选择在`mengpo_rules.gd`。

## 来源和版本

本次直接取得[官方卡库](https://ssr.163.com/cardmaker/)内嵌17100–17108数据，以及17102/17104/17108卡图，原文件保存在本轮输出目录。当前官网仍保留旧觉醒1/2及旧忘忧牌文，不能把“本次取得”当成最新规则保证。

[2020-11-26官方维护公告](https://www.taptap.cn/moment/80802089336308748)把觉醒加成增强为2/2。

[2024-12-26官方维护公告](https://www.taptap.cn/moment/621096374275932510)为图片公告，本次下载并实际查看了长图的标准天梯调整部分，6000–8000px附近写明忘忧的旋律已有瞬发和追加牌库底2张，并增加按当前式神等级限制牌名；8000px之后写明觉醒的敌方牌库≤12给予迅捷。玩家简评中的“少于12张”不是精确阈值，本轮采用公告的“≤12”。

[2022-10-27维护公告转载](https://m.youxi369.com/gonglue/142422.html)记载孟婆汤改为敌方式神3伤，随后移除敌方牌库底3。此项已按公告内容实现，但目前未补到官方原帖，保留待核验标记。2024官方公告同时佐证忘忧已包含2022增加的瞬发和追加底2机制。

[2023-03-09官方“有个牌局”调整](https://www.taptap.cn/moment/382962056401259069)只把该模式的奈何桥头改为使用牌后移底1，本轮普通对战保留原同名移除。搜索中另见4月1日整蛊公告，未把其中“永久昂扬/迅捷/直击/连击”当作孟婆正式基础能力。

## 已实现的行为

| 对象 | 实际行为 |
| --- | --- |
| 基础／觉醒能力 | 孟婆实际对敌方牌手造成正伤害后移底1／5；全甲、免伤、己方牌手伤害、其他来源不触发 |
| 孟婆汤 | 选择敌方式神3伤，再真实移除敌方牌库底3 |
| 意外之喜 | 正常1鬼火，敌方牌库≤16获得瞬发；真实抽2后选择弃1，可以弃原手牌或新抽牌，选择前不继续后续帧 |
| 天降之物 | 4/5形态，己方回合结束双方各移底1；不再以回合开始伤害替代 |
| 牙牙我们走 | 5/7形态及实际贯通；敌库≤16变8/10，按形态基值安装 |
| 汤盆冲撞 | 投射4伤，敌库≤16变8伤；命中牌手再触发孟婆能力 |
| 奈何桥头 | 4/6形态，双方使用牌时移除使用方手牌和牌库中的全部同名牌；实际自动响应也会触发，牌被无效仍保留使用触发 |
| 觉醒·孟婆 | 2/2加成，觉醒能力替换为底5；敌库≤12额外获得迅捷，普通出击真实减免并消耗 |
| 忘忧的旋律 | 瞬发、基础1鬼火；先选敌方式神，再选其当前等级允许的专属牌名，移除手牌／牌库同名牌后再移底2 |

忘忧候选来自敌方公开式神的卡牌目录，过滤等级并去重牌名，不根据敌方隐藏手牌或牌库生成，也不向AI提供隐藏命中数量。敌方没有携带的牌名仍可选择。当前候选排除标记为`token`的衍生牌，这一原版菜单边界仍待实机核验。

牌库数组末尾为顶，移底使用开头；移除不调用抽牌、不触发书翁的空库抽牌替代、不立即判定空库败北。实例保存到`removedCards`私有历史以区别于弃牌，事件和界面只报告手牌／牌库数量，不擅自公开被移除的隐藏牌名。意外之喜另外产生`card-discarded`事件。

增强查询不修改规则状态；实际使用保留当时的卡牌快照。所有选择均可序列化，并在验证中经过JSON往返再完成。AI处理两阶段牌名选择和强制弃牌，合法性仍走同一规则入口。两侧牌库数量及“移除N张”提示读取实际结算结果。

## 未完成核验

指定录像没有孟婆全组直接结算，后续普通维护公告尚未穷尽；不把本轮8张牌整体标成已完全还原。孟婆汤2022调整的官方原帖、牌名候选是否包括衍生／皮肤的所有边界、无可选牌名时能否使用忘忧、同时气绝反击后基础能力以及复制自动施法与“牌手使用”措辞的边界仍需原版确认。当前忘忧按被选择敌方式神的等级过滤，保留该项待核验。

旧HTML/JS执行器未接入这些Godot专规，不能因共享牌文覆盖就视作另一个执行器同步完成。全库审计继续严格失败；本次只把这8张牌和1个单位的明确近似移入“已实现但待核验”分类，没有降低全库验收门槛。
