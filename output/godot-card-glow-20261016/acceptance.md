# 卡边光效与惠比寿升级机制验收

本轮实际完成 Godot 瞬发蓝色上升光、昂扬黄色上升光；修正惠比寿本体、赐福 `c20901`、觉醒·惠比寿 `c20905`。结算、合法目标、真实点击、状态展示和 AI 一起接入。

瞬发蓝光以实际 `usesInstant` 及当前合法性为准，支付后取消其余牌的减免光效。昂扬相关黄光本轮覆盖已还原的惠比寿牌及真正持有昂扬且可以出击的式神；其他角色的旧近似条目未批量点亮。昂扬只减免普通出击次数，与迅捷及鬼火费用分开，战斗牌不消耗。

惠比寿改为真实升级赐福；觉醒改为升级时给予该式神 +1/+1 和昂扬，不再立即强化全队。赐福使用官方 2025-08-21 新版：自选己方最低等级、随机敌方最低等级各升一级，之后抽牌。升级入口同时触发阳炎响应，赐福的后续升级／抽牌用继续帧保留顺序。

## 验证结果

- 最终 `verify_card_aura.gd`：**35 项通过，0 失败**，包含规则正反例、AI 及实际鼠标选择与出击；原生画面在 1600×740 查看。
- Godot 4.6.3 Web 导入、导出通过，构建体积 **89.8 MiB**；生产脚本与内容文件的导出副本／当前源文件 SHA256 一致。
- 浏览器实际经过主菜单、起手抉择、战斗；最终日志 `browser-final.log`，截图已查看。
- `git diff --check` 通过。
- `npm run audit:rules` **按预期 exit 1**：明确近似卡牌 944→942，明确近似式神 142→141；未核对 795 张、待核验 170 张，已建立原生来源项仍为207；19条既存审计错误未被隐藏。

按用户要求没有重跑全量脚本、Node 测试和大量 AI 对局。初版33项通过后，收尾发现卡牌升级遗漏阳炎响应，补齐后复查同一脚本并重新导出；新增响应断言首次误写为1回合眩晕，按已有规则修正为己方回合施加须持续至下个己方回合结束的2计数，最终35项通过。没有放宽业务条件。
